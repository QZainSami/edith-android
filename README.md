# 🤖 EDITH Android

A native **Kotlin + Jetpack Compose** companion app for EDITH: chat, expressive OLED faces, a clock/weather dashboard and focus timers.

```text
Android app → Python backend → LM Studio / local model
                            → ESP32-S3 → OLED
```

Related projects: [EDITH Backend](https://github.com/QZainSami/edith-backend) · [EDITH Middleware](https://github.com/QZainSami/edith-middleware)

## ✨ Features

- 💬 Chat with EDITH, using six recent exchanges for context.
- 🟢 Separate **Backend / Model / ESP32** indicators; unavailable services turn red.
- 😊 Eight face controls and an animated display preview.
- 💤 Sleep dashboard with date, clock, city, temperature and humidity.
- ⏱️ Timers from **1 second to 24 hours**, with cancel/dismiss.
- 🌍 City search and the phone's current time-zone offset.
- ⚡ Silent display polling about every 750 ms; independent model checks about every 15 seconds.
- 🔐 Configurable backend URL and web login; credentials are not embedded in source.

**The app needs the separate EDITH backend.** It does not run Gemma or host the backend. For the current local setup, your computer must remain awake with the backend and LM Studio running. Voice, wake word, spoken audio and touch integration are future features.

## 🧰 Requirements

- [Git](https://git-scm.com/downloads) and [Android Studio](https://developer.android.com/studio).
- An Android **8.0 / API 26 or newer** phone, or an emulator.
- Internet for the first build, dependency downloads and weather.

The project currently uses **compile/target SDK 37**, **Android Gradle Plugin 9.5.0**, **Gradle 9.6.0** and **Kotlin 2.2.10**. Install an Android Studio version supporting those versions; keep the supplied build settings instead of generating a replacement project.

Gradle's daemon configuration requests **JDK 25** and can provision it automatically. Use Android Studio's bundled runtime to launch Gradle. `JavaVersion.VERSION_11` in the build file refers to generated bytecode, not the JDK required to run Gradle. No separate system Gradle or Kotlin installation is needed.

## 🪟 Windows quick start

### 1. Clone

Install Git and Android Studio, then open PowerShell wherever you keep projects:

```powershell
git clone https://github.com/QZainSami/edith-android.git
cd edith-android
```

### 2. Open and run

1. In Android Studio, choose **File → Open** and select the cloned folder.
2. Let **Gradle sync** finish.
3. In **Tools → SDK Manager**, install **Android SDK Platform 37**, the requested Build Tools and **Android SDK Platform-Tools**. Complete any SDK agreements yourself when prompted.
4. Create an emulator in **Tools → Device Manager**, or connect a phone using a data-capable USB cable.
5. For a phone, enable **Developer options → USB debugging**, unlock it and approve the computer's debugging prompt. Some brands need an [OEM USB driver](https://developer.android.com/studio/run/oem-usb).
6. Select the device beside the **app** configuration and click **Run ▶**.

Android Studio creates `local.properties` with this computer's SDK path. That file stays out of Git.

### 3. Optional terminal build

After opening/syncing once, run this from the repository root. If Java is not on PATH, set `JAVA_HOME` to Android Studio's actual `jbr` folder; this example uses its default Windows installation:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

Replace the runtime path if you installed Android Studio elsewhere. To install on one connected, authorized device:

```powershell
.\gradlew.bat installDebug
```

## 🐧 Linux / CachyOS KDE quick start

### 1. Install tools

For CachyOS / Arch:

```bash
sudo pacman -Syu --needed git android-tools android-udev
```

[android-tools](https://archlinux.org/packages/extra/x86_64/android-tools/) provides ADB; [android-udev](https://archlinux.org/packages/extra/any/android-udev/) supplies Android device access rules. The Android packages are useful for USB development, not required merely to clone the source.

Download the Linux archive from the [official Android Studio site](https://developer.android.com/studio). Extract it with KDE Dolphin wherever you keep applications. From the directory containing the extracted `android-studio` folder:

```bash
./android-studio/bin/studio.sh
```

Complete the setup wizard and install the requested SDK components. CachyOS is Arch-based and is not specifically certified by Google; check the [official installation requirements](https://developer.android.com/studio/install) if libraries are missing. Do not run Android Studio as root.

### 2. Clone and run

```bash
git clone https://github.com/QZainSami/edith-android.git
cd edith-android
chmod +x gradlew
```

Open the folder in Android Studio, let Gradle sync, and install **SDK Platform 37**, requested Build Tools and **Platform-Tools** through **Tools → SDK Manager**. Select an emulator or phone and click **Run ▶**.

For USB phones, enable USB debugging and approve the prompt. Reconnect after installing udev rules. If access is denied, check your device's udev rule and group permissions rather than running ADB or Android Studio as root. The emulator additionally needs working virtualization/KVM; a physical phone is an alternative. See [Android's device setup guide](https://developer.android.com/studio/run/device).

### 3. Optional terminal build

Use Android Studio's terminal or point `JAVA_HOME` to its actual bundled runtime:

```bash
export JAVA_HOME="/path/to/android-studio/jbr"
./gradlew assembleDebug testDebugUnitTest lintDebug
```

Replace `/path/to/android-studio` first. To install on one connected, authorized device:

```bash
./gradlew installDebug
```

If the SDK cannot be found, open the project in Android Studio once so it creates `local.properties`, or configure `ANDROID_HOME` for your installation. Each machine needs its own SDK and local configuration; do not copy the Windows SDK or `local.properties` to Linux.

## 🔗 Connect to your EDITH backend

### 1. Start the backend

Follow the separate [backend README](https://github.com/QZainSami/edith-backend#readme) to configure its private `.env`, LM Studio and ESP32 connection. From the **backend's folder**, on Windows or Linux:

```text
uv sync --locked
uv run python -m uvicorn app:app --host 0.0.0.0 --port 8000 --workers 1
```

Keep the terminal open. No backend credentials or ESP32 tokens should be added to the Android source.

### 2. Configure the app

Open **Settings** in the app:

| Device | Backend URL |
| --- | --- |
| Emulator on the same computer as the backend | `http://10.0.2.2:8000` |
| Real phone on the same reachable network | `http://YOUR-COMPUTER-LAN-IP:8000` |
| Future hosted backend | `https://YOUR-HOST` |

Find the computer's LAN IP using `ipconfig` on Windows, or `ip -4 address` and `ip route` on Linux. Addresses may change when switching computers or networks.

**`10.0.2.2` works only inside the emulator.** `localhost` / `127.0.0.1` on a real phone refer to the phone itself. [Emulator networking reference](https://developer.android.com/studio/run/emulator-networking-address)

If authentication is enabled, enter the backend's **`EDITH_WEB_USER` and `EDITH_WEB_PASSWORD`**, then tap **Save & connect**. These are not the device token or LM Studio key. Leave them blank only when the backend has no web authentication.

On Android 17+, tap **Allow local network** and approve it before connecting to your PC. If permanently denied, enable the permission in Android's app settings. [Local-network permission reference](https://developer.android.com/privacy-and-security/local-network-permission)

Keep phone and computer on a reachable network. Allow inbound TCP port 8000 only on the computer's trusted LAN using its firewall; do not disable the firewall. Guest Wi-Fi, some hotspots and VPNs can isolate devices. If the app times out, open the same backend URL in the phone's browser first.

## 🎮 Use the app

- **Chat:** talk to EDITH, or type `EDITH sleep`, `EDITH wake up`, `set a timer for 5 minutes`, or `cancel timer`.
- **Controls:** change faces, sleep/wake, start/dismiss timers, search and select a weather city.
- **Settings:** change backend connection or check LM Studio.
- **Preview:** face/screen requests appear immediately with **Syncing with OLED** until confirmed. Faces, speaking movement, clock/weather and timers are reconstructed from state, not a streamed framebuffer. Physical timing depends on the network and ESP32 polling; animations are approximate.
- **Model status:** green means LM Studio is reachable, the configured model is listed and AI mode is enabled. It does not test a full generation; replies can still fall back to labeled rules.

Timers belong to the backend/ESP32, so closing the app does not cancel them. The clock uses the phone's offset when settings/controls are submitted; save again after changing time zone or daylight-saving offset. Weather uses [Open-Meteo](https://open-meteo.com/). Timers currently have visual alerts only, without a speaker alarm.

## 📦 APK and verification

The build commands above produce:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Install over an existing build signed with the same key. Each computer normally generates a different debug key: switching build machines may require uninstalling the previous debug app first, removing its saved settings. Do not commit signing keys. For future distribution, use private release signing and GitHub Releases for APK downloads instead of committing generated binaries.

Windows builds, tests, emulator operation and real-phone-to-OLED operation have been checked during development. Native CachyOS builds and hardware operation have not yet been verified.

## 🔒 Privacy and local files

- URL and username persist in app-private preferences. Password stays in memory and must be re-entered after a cold start.
- Chat stays in memory; clearing chat, switching backend or process termination discards it. Recent exchanges go to your configured backend/model.
- Automatic checks start after connecting and pause on connection failure. Display checks are silent, do not shift the UI and continue during model replies. Model checks run separately. No background service is installed.
- Debug builds permit HTTP only to local IPv4/localhost addresses for trusted development. HTTP is unencrypted. Release builds require HTTPS; certificate checks stay enabled and redirects are rejected.
- Microphone, location, storage and notification permissions are not requested. Android 17 local-network access is used for connecting to the backend.
- `.gitignore` excludes local SDK paths, IDE state, caches, APKs, private environment files and signing material. Wrapper scripts/JAR and version catalog are deliberately included.

## 🔄 Work across Windows and Linux

Clone separately on each machine. Before working:

```bash
git pull --ff-only
```

After editing:

```bash
git add .
git diff --cached --stat
git commit -m "Describe the change"
git push
```

Keep SDKs, caches and secrets local to each machine. Commit or deliberately stash unfinished work before pulling. `.gitattributes` preserves LF for Linux scripts and CRLF for Windows batch files.

## ☁️ First upload to GitHub

Create an **empty** repository on GitHub. Leave its README, license and .gitignore options unchecked because this project supplies them. Follow [GitHub's existing-project guide](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github).

From a source folder not already tracked by Git:

```bash
git init -b main
git add .
git update-index --chmod=+x gradlew
git diff --cached --stat
git commit -m "Initial EDITH Android app with chat, controls and live display preview"
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main
```

Replace the remote URL. If a local repository/remote already exists, inspect `git status` and `git remote -v` before adding another. Use GitHub's supported Git sign-in flow, not your account password as a Git HTTPS password. Do not force-push to bypass a non-empty remote.
